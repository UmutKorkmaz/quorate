How it works

From install to insight
in three steps

No YAML to write, no secrets to configure per repo. Install once, cover your whole organization.

  1. ⚡
    01

    Install the App

    Add Quorate to your GitHub organization or individual repositories in one click via the App manifest flow. No workflow files needed.

  2. 🔀
    02

    Open a Pull Request

    Push a branch and open a PR as usual. Quorate's webhook fires automatically and the council begins — no manual trigger required.

  3. 🏛️
    03

    Get the verdict

    A native Check Run appears alongside your CI. Inline annotations pin findings to exact lines. A PR comment summarizes the full council report with your PASS / WARN / FAIL verdict.

What you get

Built into GitHub,
not bolted on

Quorate speaks GitHub's native APIs so the results live exactly where your team already works.

  • ✅

    Native Check Run UI

    Results appear in the Checks tab alongside your CI. Required status checks, branch protection rules, and merge queues all work naturally.

  • 📌

    Inline annotations

    Findings with a file and line are pinned directly to the diff. Reviewers see context without leaving the PR.

  • 🔍

    Auto-detected domain packs

    Quorate inspects the changed files and activates the right domain-specific pack — security, infrastructure, API design — automatically.

  • 🏛️

    One verdict per PR

    PASS, WARN, or FAIL — a clear signal from the full council, configurable against your branch protection rules.

  • 🔄

    Re-run button

    Click Re-run in the Checks tab to trigger a fresh council run after addressing feedback. No extra workflow dispatch needed.

  • ⚙️

    Zero per-repo config

    Works out of the box with sensible defaults. Drop a .quorate.yml into any repo to fine-tune providers, councils, or fail thresholds.
