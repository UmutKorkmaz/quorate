# Verify a distributed release

`quorate release verify --manifest release.json --json` verifies explicitly selected npm packages and public GitHub assets. It never publishes, tags, creates a release, or repairs production. `quorate release status --report .quorate/releases/latest.json` validates and displays saved evidence without executing commands or contacting providers.

Use a trusted manifest reviewed separately from the proposed artifact. Supply schemaVersion `1`, the expected full `sourceRevision`, and `destinations`. The source revision identifies the manifest's subject; independent source verification is required only when a destination declares `expectedSourceRevision`. An npm destination needs `id`, `kind: "npm"`, `package`, exact `version`, and expected `expectedIntegrity` (`sha512-` SRI). A GitHub destination needs `id`, `kind: "github"`, `repository` (`owner/repository`), `tag`, immutable numeric `assetId`, exact asset `name`, and `expectedSha256`.

Optional `submission` is `accepted`, `rejected`, or `unknown`. It records supplied submission evidence; availability never implies a submission receipt. Optional `expectedSourceRevision` and `expectedProvenanceDigest` add independent required checks. Missing required source/provenance remains unknown; a mismatch fails. npm provenance digest means the hash of the registry-provided attestation document, not independent verification of its signer. GitHub assets currently support public downloads; private assets or unresolved commit identities remain inconclusive. Retained reports always identify the local producer as **unattested**.

The npm adapter uses the official registry, installs the exact version with lifecycle scripts disabled in an owned disposable prefix/home/cache, checks installed package identity and lockfile integrity, and runs version/help plus clean and blocked supply-chain gates. Packages must expose the Quorate-compatible CLI journey. GitHub metadata uses literal read-only `gh api --hostname github.com ... --method GET` requests; asset bytes come from the immutable official API asset-ID endpoint with an octet-stream Accept header. Mutable tag/name browser URLs are ignored. Redirects are checked before following them against a fixed official API/CDN host allowlist, with a maximum of five redirects and one shared deadline. Downloads are bounded to 64 MiB. Authentication stays in the existing `gh` configuration and is never copied into a report.

`deadlineMs` defaults to `600000` and cannot exceed that value. Recovery retains the first report's deadline, immutable identities, observation history, verified destinations and terminal mismatches. Rerunning the same manifest repeats pending verification, without resubmission. Manifests with different identities produce different report paths. Reports live under `.quorate/releases/<manifest-digest>.json`, with a latest pointer copy. Do not alter an existing report to extend its deadline; a deliberately fresh verification uses a separately reviewed manifest. Concurrent verification of the same manifest is unsupported.

Destination states are `planned`, `submitted`, `available`, `verified`, `failed`, and `unknown`. Available metadata alone never verifies installation. A missing artifact at the bounded deadline fails; an ambiguous provider response remains inconclusive. Partial destination success remains visible. Exit `0` means every required selected check passed, `1` means a hard failure or missing evidence at the deadline, and `2` means invalid/inconclusive input or execution. Output does not authenticate a remote producer. Native installation and the default bounded npm/gh command adapters support Linux and macOS. On Windows, native install smoke stays unknown/inconclusive and cannot produce verified distribution evidence; default provider CLI observations likewise remain unknown. Saved report inspection and explicitly injected read-only availability adapters are cross-platform. No Windows process-containment support is claimed.

The deterministic test corpus freezes eight scenarios: fully available, delayed npm metadata, delayed installation, wrong version, wrong digest, missing GitHub asset, rejected submission, and mixed destination success. The owned native package test additionally exercises real npm pack/install, version/help and both gates. These fixture results do not prove an actual public release; verify each exact published candidate separately after the reviewed release workflow completes.
